# go-amt-ipld agent guide

go-amt-ipld is the Go AMT used for Filecoin actor state, block messages, receipts and events. Its blocks must match [ref-fvm](https://github.com/filecoin-project/ref-fvm)'s `ipld/amt` byte for byte: Lotus and Forest compute the same roots from them, so an encoding change is a consensus change.

`doc.go` describes the algorithm and `internal/internal.go` the wire schemas. Read them before changing encoding, structure or load validation, and update them in the same PR.

## Format rules

- The root records its bitwidth, and `LoadAMT` rejects a mismatch with the caller's option. Each Filecoin structure has its own bitwidth, so callers pass the structure's constant.
- The node bitmap is fixed-length and LSB-first within each byte, unlike the HAMT's minimal big-endian bitfield. `internal/cbor_gen.go` is generated by `go run ./gen`.
- Height growth, collapse on delete and empty-node pruning decide the root, so a change to them is a format change even when every block still decodes. The root's count is checked only against the height's capacity; `Len()` returns it as stored.
- A new load rejection rule must not reject blocks Rust writes, and loosening validation must not admit blocks Rust rejects.
- A format change lands in Rust and Go together.

## Versions and consumers

- `master` is v4, imported by [go-state-types](https://github.com/filecoin-project/go-state-types) for actor state and by Lotus for events.
- `release/v2` is live consensus too: Lotus builds block message and receipt AMTs with it, directly and through specs-actors.
- A fix on either branch must leave every root unchanged.

## Testing

- `go test ./...`. `TestCidStability` and `TestEmptyCIDStability` pin roots; a change that moves one is a format change. `fuzz/` replays operation sequences against a model.
- Go tests show Go agrees with itself. For a behaviour change, compare roots and blocks with ref-fvm's `ipld/amt` on the same operations.

## Comments, commits and pull requests

- Write comments and docs year-zero, describing the code as it is; history goes in the commit message and PR description. A comment states what a maintainer can't read from the code: an invariant, a format constraint, a surprising cost.
- PR titles use Conventional Commits, with `!` before the colon for a change that breaks importers.
- Report suspected vulnerabilities as the [Filecoin security policy](https://github.com/filecoin-project/community/blob/master/SECURITY.md) describes, never in a public issue or PR.
